## Tier model
| tier | id | plan_id (unchanged, stored in DB) | display label |
|---|---|---|---|
| Ananta | 1 | `ananta` | Ananta |
| Yanta | 2 | `yanta` | Yanta |
| Trika | 3 | `trika` | Trika |
| Parth | 4 | `part` | **Parth** (was "Part") |

The third tier is spelled `Trika`, never with a double k. `plan_id` values stay as stored; only the
`display_name` of `part` becomes `Parth`.

## Contract
- `users` gains `unlocked_tier INTEGER NOT NULL DEFAULT 1` and `active_theme INTEGER NOT NULL DEFAULT 1`,
  with CHECK constraints `unlocked_tier BETWEEN 1 AND 4`, `active_theme BETWEEN 1 AND 4`,
  `active_theme <= unlocked_tier` (new Alembic migration + model change together; batch mode for SQLite).
- `unlocked_tier` is derived from the account's *effective* plan (`services.plan_policy`, so a
  cancelled / inactive subscription unlocks tier 1 only). Stored value is kept in sync server-side.
- `services.sync_theme_progression(session, user) -> None`: sets `unlocked_tier` from the effective
  plan; if `active_theme > unlocked_tier`, resets `active_theme = unlocked_tier` (safe downgrade).
  Also `sync_account_progression(session, account_id)` for all users of an account.
- The billing sandbox webhook calls `sync_account_progression` after it changes `plan_id`/status
  (same transaction), so downgrades revert themes immediately.
- `GET /v1/armory` (auth) → `ArmoryView {unlocked_tier:int, active_theme:int, tiers:[{id:int,
  key:str, label:str, plan_id:str}]}` (4 entries, id order). Syncs before responding (commit if changed).
- `PUT /v1/armory/active-theme` (auth) body `{active_theme:int}`:
  - 422 if not an int in 1..4 (pydantic `Field(ge=1, le=4)`; reject bools/strings).
  - Syncs first; if `active_theme > unlocked_tier` → **403** `detail={"code":"TIER_LOCKED",
    "unlocked_tier":n}` and nothing changes.
  - Else stores it and returns `ArmoryView`.
- Themes never change agent behaviour: no other endpoint reads `active_theme`.

## Acceptance

  `active_theme`; cancelled subscription → tier 1; plan→tier mapping; check constraints reject
  `active_theme > unlocked_tier` at the DB level (IntegrityError).
- E2E: 401 without token; defaults (1,1); activating locked tier → 403 + unchanged; invalid values

  account has independent `active_theme`; other accounts unaffected; `/v1/messages` behaves the same
  regardless of active theme.
