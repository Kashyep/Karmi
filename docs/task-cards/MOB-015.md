# MOB-015: Tier themes, Liquid Glass tint, Armory and app icons (Flutter)

- Plan: `docs/design/implementation_plan.md` (§1–4), palettes `docs/design/karmi_tier_color_palettes.md`
- Depends on: API-002 (`GET /v1/armory`, `PUT /v1/armory/active-theme`)
- Base commit: `9f6e726`

## Mapping the plan onto the Flutter client
| Plan item | Implementation |
| --- | --- |
| CSS tokens (`--color-canvas`, `--color-glass-base`, …) | `KarmiColors` ThemeExtension, generated per tier × mode by `mobile/tool/derive_theme_tokens.py` into `lib/theme/tier_tokens.g.dart` (the same generator writes the web `karmi-tokens.css`) |
| `<html data-tier data-theme>` + O(1) switch | `KarmiApp` picks `KarmiTheme.of(tier, brightness)` from a cache; `KarmiTierTheme` extension exposes the tier; mode = `KarmiSettings.themeMode` (System/Light/Dark, persisted, follows the OS) |
| ThemeContext (dual axis) | `KarmiSettings` (mode) + `ArmoryController` (tier) merged at the root |
| `.glass-panel` + fallback | `KarmiGlassSurface`: tier `glassBase` tint at the legibility floor, 1px rim, top highlight, hover/pressed states; opaque `--card` + `--border` under reduce transparency / high contrast |
| Armory `unlocked_tier`/`active_theme` | Server-authoritative (API-002); `ArmoryController` caches the last values, clamps `active ≤ unlocked`, re-syncs on 403 |
| Gallery route, locked UI | `ArmoryScreen` (overflow menu → Armory, Settings → Armory): blur(4) + 80% greyscale + padlock, Activate disabled for locked tiers |
| 10-second preview | `ArmoryController.startPreview` — single timer + token; cancelled by a new preview, activation, unlock, sign-out, dispose; pinned countdown banner with End preview, also shown over every shell tab |
| Native icon switching | Android `<activity-alias>` per tier toggled in `MainActivity.kt` — applied in `onStop` (or at once if already backgrounded) because disabling the running task's alias destroys the task (observed on the Pixel 9a: the first, immediate implementation killed the app and the Mali driver aborted during teardown); iOS `setAlternateIconName` in `AppDelegate.swift` with `AppIcon-<Tier>` sets; channel `ai.karmi.app/app_icon` |
| Component decoupling | Business logic (API client, chat, tasks, memory, usage) takes no tier input; tier only changes `ThemeData`; tested by "agent behaviour is identical in every tier" |

## Verification
- `test/theme/karmi_colors_test.dart`: palette hexes used unchanged; WCAG AA for text on
  background/card/muted, ink on fills, 3:1 borders/focus, text over glass on 5 worst-case backdrops,
  disabled buttons — for all 8 tier × mode combinations; cached theme lookup.
- `test/armory/armory_controller_test.dart` (21): init/cache/corrupt cache, invalid tiers, activation,
  locked refusal, 403 race, upgrade, downgrade, stale-response ordering, sign-out reset, preview
  10 s revert, timer replacement, early end, dispose cleanup, previews never hit the server.
- `test/features/armory_test.dart` (17): initial tier, mode switch persistence, gallery lock UI,
  activation re-themes the app + native icon call, preview/revert, downgrade, sign-out, identical
  agent requests in every tier, a11y guidelines in all 8 combinations (chat, settings, armory).
- Goldens: `tier_chat_*` and `tier_armory_*` for all 8 combinations (Windows + Linux).

- Pixel 9a (Android 17), debug build against the local backend: with `active_theme` = Parth the
  app kept running under `.LauncherYanta` with `pending_tier=parth`; after Home the launcher entry
  was `.LauncherParth`, no crash, and relaunching through `.LauncherParth` worked (Parth dark theme
  rendered). Downgrading the synthetic account to Ananta reverted the launcher to `.LauncherAnanta`.
- Flutter 3.47.5 gates on the implementation tree: format (0 changed), analyze
  (0 issues), `flutter test` (319 incl. 90 Windows goldens), Linux container
  goldens (90), and release Android appbundle (52.0 MB) passed.
- `python mobile/tool/generate_app_icons.py` regenerated all four tiers.
- PR #20 follow-up: Ubuntu `textContrastGuideline` sampled the pale status
  chip immediately above the Yanta tagline (not the dark tagline ink); added
  8px between the chip row and tagline. Kept palette, derived tokens and
  accessibility assertions unchanged. Windows and Linux non-golden suites
  each passed 229 tests; refreshed and verified 90 goldens on each OS.
