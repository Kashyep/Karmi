# API-001 — Account-scoped task list (`GET /v1/tasks`)

- Requirements: UI_IMPLEMENTATION_PLAN.md §6 gap "No `GET /v1/tasks`" (Q4); ADR-0002 Q4 resolution
- Base commit: `67e478b`
- Owner: backend worker (Boss integrates)
- File ownership: `src/daily_agent/api.py`, `src/daily_agent/services.py`, `tests/e2e/test_api.py`,
  `tests/unit/**` (only if a unit test is added), this card's Status section
- Contract:
  - `GET /v1/tasks` requires `Bearer` auth (`require_principal`); returns `list[TaskView]`
    (`{id, title, completed}`), no new schema fields, no migration.
  - Scoped by `account_id` only (tasks are account-shared by design, see CLAUDE.md), never by
    another account's rows.
  - Deterministic order: open tasks first, then completed; ties by title then id (the `tasks` table
    has no creation timestamp; adding one needs a migration and is out of scope).
  - Query lives in `services.py` (`scoped_task_query(account_id)`), handler in `api.py` stays thin.
- Acceptance:
  - E2E test covers: 401 without token; empty list; two accounts' tasks do not leak across
    accounts; a second user of the same account sees the account's tasks; completed state and
    ordering after `PATCH /v1/tasks/{id}/complete`.
  - `python scripts/tasks.py lint`, `typecheck`, `test-unit`, `test-e2e` all pass.
- Constraints: no schema/migration change; no Memory.md edits; no dependency changes.
